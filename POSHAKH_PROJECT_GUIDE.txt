2. PROBLEM STATEMENT & THE POSHAKH SOLUTION
--------------------------------------------------------------------------------
PROBLEM (Traditional Offline System):
- High Retail Cost: Families spend Rs. 40,000 to Rs. 1,50,000 on bridal lehengas 
  or groom sherwanis that are worn only once for a single evening.
- Dead Wardrobe Capital: Millions worth of designer apparel sits idle in cupboards.
- Insecure Deposits: Local offline rental shops take cash deposits with no written 
  contracts or dispute protection.
- Sizing Ambiguity: Renters travel to physical shops with zero catalog visibility.

SOLUTION (The Poshakh Circular Ecosystem):
- 85%+ Cost Savings: Rent an authentic Rs. 65,000 royal lehenga for just Rs. 3,800.
- 100% Security Escrow: Transparent security deposits held safely until return 
  inspection passes.
- Direct Boutique Chat: Renters chat directly with boutique curators for blouse 
  fittings, custom measurements, and delivery updates.
- Lender Monetization: Ethnic boutiques & wardrobe owners earn recurring revenue 
  from idle couture garments.
- Impartial Admin Governance: Super Admin arbitrates damage claims with photo proof.


3. USER ROLES & ACCESS CONTROL (RBAC)
--------------------------------------------------------------------------------
A) CUSTOMER / RENTER:
   - Can browse catalog and filter by Category, Occasion, Price, and Boutique.
   - Can select rental duration (3, 5, or 7 days) with dynamic price calculation.
   - Can pay Rental Fee + Refundable Security Deposit via simulated escrow.
   - Can chat in real-time with boutique lenders before and after booking.
   - Can track active rentals, view tracking IDs, and submit return requests.
   - Restriction: Cannot edit boutique inventory or access admin portals.

B) BOUTIQUE LENDER:
   - Has a dedicated Boutique Storefront with bio, city, rating, and avatar.
   - Can list new garments with titles, categories, rental prices, and deposit sums.
   - Can toggle garment availability (Available vs Rented) and manage stock.
   - Can track incoming rental orders and mark garments as Dispatched with tracking.
   - Can inspect returned outfits and confirm condition to release deposit.
   - Restriction: Cannot unilaterally withhold deposits or change platform fees.

C) SUPER ADMINISTRATOR:
   - Super Admin credentials: admin202@admin.com / Admin@202
   - Full access to Admin Portal (admin.html).
   - Monitors global platform KPIs: Total Revenue, Active Bookings, Total Users.
   - Oversees the Dispute Arbitration Desk to mediate damage complaints.
   - Has authority to execute deposit refunds or authorize damage deductions.

6. DATABASE TABLES & DATA SCHEMAS
--------------------------------------------------------------------------------
Table 1: USERS
- id (PK)                 : VARCHAR - Unique user identifier
- name                    : VARCHAR - User full name
- email (UK)              : VARCHAR - Login email address
- password                : VARCHAR - Encrypted password
- role                    : ENUM    - 'renter' | 'lender' | 'admin'
- phone                   : VARCHAR - Contact number
- avatar                  : VARCHAR - Profile picture image URL

Table 2: LENDERS (Boutiques)
- id (PK, FK -> USERS)    : VARCHAR - Boutique unique handle (e.g. 'radha')
- boutiqueName            : VARCHAR - Business name (e.g. 'Radha Ethnic House')
- handle                  : VARCHAR - Unique username (e.g. '@radha_poshakh')
- bio                     : TEXT    - Boutique heritage description
- rating                  : FLOAT   - Average satisfaction score (e.g. 4.9)
- location                : VARCHAR - Geographic city (e.g. 'Ahmedabad, Gujarat')
- totalRentals            : INT     - Lifetime completed rentals count
- status                  : VARCHAR - 'Verified Boutique' badge

Table 3: DRESSES
- id (PK)                 : VARCHAR - Garment code (e.g. 'd1')
- name                    : VARCHAR - Outfit title (e.g. 'Crimson Bridal Lehenga')
- category                : VARCHAR - 'Lehenga', 'Saree', 'Sherwani', 'Chaniya Choli'
- occasion                : VARCHAR - 'Wedding', 'Sangeet', 'Navratri', 'Reception'
- rentPrice               : INT     - 3-day rental fee in INR (e.g. 3800)
- deposit                 : INT     - Refundable security escrow sum (e.g. 6000)
- retailValue             : INT     - Original retail purchase price (e.g. 65000)
- lenderId (FK -> LENDERS): VARCHAR - Owner boutique identifier
- fabric                  : VARCHAR - Textile material and embroidery details
- images                  : ARRAY   - High-resolution photographic URLs
- availability            : BOOLEAN - In-stock toggle for rental

Table 4: ORDERS
- orderId (PK)            : VARCHAR - Transaction ID (e.g. 'ORD-2026-9812')
- dressId (FK -> DRESSES) : VARCHAR - Reference to rented garment
- renterId (FK -> USERS)  : VARCHAR - Customer user reference
- lenderId (FK -> LENDERS): VARCHAR - Fulfilling boutique reference
- rentalDays              : INT     - 3, 5, or 7 days duration
- totalAmount             : INT     - Rent Fee + Security Deposit + Delivery
- status                  : ENUM    - 'Booked', 'Dispatched', 'Active', 'Returned'
- escrowStatus            : ENUM    - 'HELD', 'REFUNDED', 'DISPUTED'

Table 5: CHATS
- id (PK)                 : VARCHAR - Unique chat message ID
- senderId (FK -> USERS)  : VARCHAR - Author user ID
- receiverId (FK -> USERS): VARCHAR - Recipient user ID
- text                    : TEXT    - Message content
- timestamp               : DATETIME- Dispatch time

Table 6: COMPLAINTS
- complaintId (PK)        : VARCHAR - Dispute case number
- orderId (FK -> ORDERS)  : VARCHAR - Related rental order
- filedBy (FK -> USERS)   : VARCHAR - Reporting user ID
- reason                  : VARCHAR - Description of damage or sizing issue
- claimAmount             : INT     - Claimed compensation deduction
- status                  : ENUM    - 'Pending', 'Investigating', 'Resolved'


7. STEP-BY-STEP WORKFLOW: HOW IT WORKS
--------------------------------------------------------------------------------
STEP 1: LOGIN & ROLE ROUTING
- User visits login.html.
- Renter logs in -> redirected to shop.html.
- Boutique Lender logs in -> redirected to lender-dashboard.html.
- Admin logs in (admin202@admin.com / Admin@202) -> redirected to admin.html.

STEP 2: OUTFIT SELECTION & PRICING
- Customer selects an outfit on shop.html and opens product.html.
- Customer toggles rental duration (3 Days = 1x rent, 5 Days = 1.5x, 7 Days = 2x).
- System displays: Net Rent + Refundable Security Deposit = Total Due.
- Customer can click "Chat with Boutique" to confirm sizing before booking.

STEP 3: ESCROW PAYMENT & DISPATCH
- Customer confirms booking on checkout.html.
- Total amount is charged; Security Deposit is locked into 'HELD' escrow status.
- Boutique Lender sees order on lender-dashboard.html, packs outfit, and clicks 
  "Mark Dispatched", adding a courier tracking code.

STEP 4: RETURN & AUTO-REFUND
- Customer wears outfit for the event and returns it via courier.
- Boutique receives outfit and inspects condition.
- If condition is satisfactory, Boutique clicks "Confirm Return Received".
- Order completes, escrow status switches to 'REFUNDED', and deposit is returned.
- If damage is found, a claim is submitted and Super Admin resolves the dispute.

9. TOP VIVA DEFENSE QUESTIONS & ANSWERS (LJCCA)
--------------------------------------------------------------------------------
Q1: What is the core business and technical innovation in Poshakh?
A:  Poshakh converts single-use high-expense bridal couture into a circular 
    sharing economy. Technically, it implements dynamic date-based rental 
    calculation, real-time pre-booking chat, and a deterministic security deposit 
    escrow system that protects both renters and boutique lenders.

Q2: Why use a custom Node.js server instead of standard Apache or XAMPP?
A:  Our native Node.js HTTP server (server.js) is self-contained and zero-dependency. 
    It eliminates heavy server installations, provides precise MIME-type mapping 
    for modern web formats, and ensures cross-platform portability.

Q3: How are security deposits protected from fraud?
A:  Neither the renter nor the lender can unilaterally take funds. Security deposits 
    remain in escrow until both return delivery and physical inspection are certified. 
    In case of disagreement, disputes are arbitrated exclusively by the Super Admin.
